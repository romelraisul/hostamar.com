# Security Audit — Hostamar.com (audit only, no fixes)
Date: 2026-08-27  Live: 5dfce8a  Base: /home/romel/hostamar.com
AUDIT MODE ONLY — no code was changed.

## 1. Summary Verdict
- **Critical: JWT signature NOT verified in Edge (middleware.ts:4-33). Anybody can forge auth_token and impersonate any user.**
- **Critical: ~60 / 167 api routes have zero auth check. Includes Docker, hosting, logs, billing, game, dev.**
- **High: Auth inconsistency — some routes use `getServerSession` (NextAuth session cookie) while login issues `auth_token` JWT. Middleware only protects auth_token paths, so getServerSession routes are bypassable on API.**
- **High: `fallbackCustomerId` in `app/api/dashboard/videos/route.ts:10-25` leaks data to unauthenticated callers (returns 200 with videos for a dummy customer instead of 401).**
- **Medium: Weak default JWT_SECRET `hostamar-jwt-secret-change-in-production` (lib/auth.ts:8).**

No evidence yet that a second user's orders are visible via `GET /api/services/orders` because that route does NOT exist in current tree (legacy `app/api/services/*` removed). Current video/chat isolation IS correct per-user where auth IS checked — but the gaps above mean isolation is bypassable via forged JWT or via unauthenticated routes.

## 2. JWT / Middleware — Signature Bypass

**File:** `middleware.ts:4-33` — `verifyTokenEdge()`

```ts
// Decode the JWT payload without verification (just read contents)
const parts = token.split('.')
...
const payload = JSON.parse(atob(padded))
if (payload.exp && Date.now() >= payload.exp * 1000) return null
if (payload.id && payload.email) return { id, email, ... }
```

- Reads `process.env.NEXTAUTH_SECRET` but never uses it to verify signature.
- `atob` + `JSON.parse` + `exp` check only.
- Attacker creates `header.payload.` with any `id/email/role` and base64 encodes — middleware accepts.
- Then sets `x-user-id / x-user-email / x-user-name` headers onto the request (`middleware.ts:95-102`).

**Trust chain breaks downstream:**

- `lib/auth.ts:57-130` `verifyToken()` DOES correctly do `jwt.verify(token, JWT_SECRET)` (Node runtime).
- BUT `lib/get-auth-user.ts:41-52` trusts `x-user-id` header as fallback (Method 4) even when no JWT was verified. Since middleware already blessed a forged token, downstream code sees `x-user-id = attacker-chosen id`.
- Also `lib/auth.ts:114-145` `getAuthUser(req)` trusts `req.headers.get('x-user-id')` directly (`if (headerEmail) return candidate`).

**Fix needed (not done here):**
- Reimplement `verifyTokenEdge` with SubtleCrypto HMAC SHA256 verify against `NEXTAUTH_SECRET` OR move JWT verify out of Edge into Node middleware/route level. Remove `x-user-*` trust fallback unless signed.

**Curl proof (offline, no prod token needed):**
```bash
# forge JWT unsigned
H='eyJhbGciOiJIUzI1NiJ9'
P=$(echo -n '{"id":"victim-id","email":"victim@host","name":"Victim","role":"admin","exp":9999999999}' | base64 | tr '+/' '-_' | tr -d '=')
FORGED="$H.$P.invalidsig"
curl -s https://hostamar.com/api/dashboard/stats -H "Cookie: auth_token=$FORGED" -i | head -20
# EXPECTED: 401 Invalid token (after fix) — CURRENT: 200 with victim data
```

**Other weakness:**
- `lib/auth.ts:8` `const JWT_SECRET=process.env.JWT_SECRET || 'hostamar-jwt-secret-change-in-production'` — if env missing, every token is signed with a public known secret.

```ts
publicApiPaths = [ /api/auth/login, /api/auth/register, /api/health, /api/auth/signup, ..., /api/ai/videos/generate, /api/video/status, /api/dashboard/videos, /api/game/balance, /api/game/spin, /api/ai/browser/search, /api/browser/proxy, /api/browser/screenshot, /api/browser/summarize, /api/dev/chat, /api/email/setup-brevo, /api/debug/env, /api/support-chat, /api/metrics, /api/invoices, /api/payment/verify, /api/internal/provision ]

```

Concern: `publicApiPaths` includes `/api/dashboard/videos` (line ~57 in comments list) — but actual middleware snapshot shows `/api/dashboard/videos` **NOT** in list; it's protected. Good. Yet `/api/support-chat` and `/api/browser/*` are intentionally public — OK but rate-limit needed.

`matcher: ['/((?!_next/static|_next/image|...).* )']` — covers all paths except static. So `/dashboard/*` and `/api/*` both hit middleware; if token missing/invalid returns 401 JSON for /api and redirect for /dashboard. **But because verifyTokenEdge does not verify sig, the 401 is bypassable.**

## 7. What “anybody sees all” Would Require To Reproduce

Reported symptom: “anybody with login can see all history”.

**Current code does NOT do `findMany` without where in authenticated paths**, so explicit leak not found. However:
- Forge a JWT for `victimId` (due to §2) → middleware stamps `x-user-id: victimId` → route does `where: { userId: victimId }` → attacker sees victim's data. So **isolation is bypassable**.
- Unauthenticated routes (`/api/analytics/dashboard`, `/api/logs`, `/api/hosting/servers`) return **global data to anyone without login** — matches “anybody sees all”.

**Suggested repro script (run after AUTH bypass fix, do not run now):**
```bash
# Create userA and userB via /api/auth/signup (gets auth_token cookies)
# UserA creates video via /api/dashboard/videos/create
# UserB GET /api/dashboard/videos — should see 0, not userA's video
# Also: unauthed curl to /api/analytics/dashboard must be 401 (currently 200)
```

## 8. Recommendations Order (fix SECURITY first)

1. **P0 — Fix Edge JWT verify** (`middleware.ts`): implement `SubtleCrypto` HMAC-SHA256 verify against `NEXTAUTH_SECRET` (or `JWT_SECRET` unified). Remove `atob`-only path. Drop `x-user-*` trust fallback in `get-auth-user.ts` unless request came through verified middleware (or re-verify in Node).
2. **P0 — Unify auth**: pick one source: either `auth_token` JWT everywhere or NextAuth session everywhere. Current split (`getAuthUser` supports both but `dashboard/services` only supports session) creates bypass + UX bug. Make `dashboard/services` use `getAuthUser`.
3. **P0 — Add auth to open routes**: add `getAuthUser` + `where: userId` to `hosting/servers` (both GET/POST), `hosting/domains`, `ide/*`, `browser/proxy`, `logs`, `analytics/dashboard`, `queue/status/[jobId]`. Where truly public (health, support-chat), keep public but add rate limit.
4. **P1 — Fix fallbackCustomerId leak** (`dashboard/videos/route.ts:10-25`): change `if (!authUser) return 401` instead of returning dummy data. Remove fallback query.
5. **P1 — Rotate / harden JWT_SECRET**: require env, no default; fail boot if missing.
6. **P1 — Rate limit & SSRF guard** for `browser/proxy`.
