## Kill Request-Data Reads in /api/services/catalog

**Commit:** 6cf5412 (FAILED build — not on remote)
**File:** `app/api/services/catalog/route.ts`
**Status:** Fixed in current HEAD (7d8bb43) — try/catch + zero request access

### Problem
`GET /api/services/catalog` returned bare `max-age=60` on Vercel production — no `s-maxage`, no `stale-while-revalidate`, no `stale-if-error`. CDN served `cf-cache-status: MISS` every probe.

Root cause: route handler read `req.url` and `req.nextUrl.searchParams` but NEVER used the values (category/search had zero callers, all filtering was client-side). Merely accessing the Request object made Next.js classify the route as **per-request dynamic**. Vercel's edge runtime strips `s-maxage`/`SWR`/`SIE` from per-request-dynamic responses, leaving only the base `max-age=60` from `next.config.js`.

Vercel build ALSO failed at this commit: `prisma.$queryRaw()` invoked during static export with no real DATABASE_URL → `Authentication failed against database server at localhost`.

### Fix (current HEAD 7d8bb43)
```typescript
export async function GET() {
  let services: Array<Record<string, unknown>> = []
  try {
    services = await prisma.serviceCatalog.findMany({
      where: { isActive: true },
      orderBy: { id: 'asc' },
    })
  } catch {
    // Build-time / no-DB: return empty catalog so static export succeeds.
  }
  return NextResponse.json({ success: true, total: services.length, services }, {
    headers: { 'Cache-Control': 'public, max-age=60, s-maxage=300, stale-while-revalidate=600, stale-if-error=3600' }
  })
}
```

- Zero Request/URL/cookie/header access → ISR-cacheable
- try/catch around Prisma → build passes with dummy env
- `s-maxage=300 + SWR=600 + SIE=3600` → CDN caches 5min, serves stale 10min while revalidating, 1h on error

## Request-Data Access That Kills Vercel Caching

| Access | Kills s-maxage/SWR/SIE? |
|--------|------------------------|
| `req.url` | YES |
| `req.nextUrl.searchParams.get(...)` | YES |
| `req.headers.get(...)` | YES |
| `req.method` | YES |
| `cookies()` (from next/headers) | YES |
| `headers()` (from next/headers) | YES |
| `export const dynamic = 'force-dynamic'` | YES (separate mechanism) |

Any of these makes the route per-request dynamic. Vercel edge strips CDN cache directives from per-request responses.

---

## Cache-Control Strategy

```
public, max-age=60, s-maxage=300, stale-while-revalidate=600, stale-if-error=3600
```

| Directive | Value | Who uses it |
|-----------|-------|------------|
| max-age=60 | 60s | Browser (sticky per-user) |
| s-maxage=300 | 5 min | CDN (Cloudflare, shared) |
| stale-while-revalidate=600 | 10 min | Serve stale while revalidating in background |
| stale-if-error=3600 | 1 hour | Serve stale on origin error |

max-age is for the browser. s-maxage is for the CDN. They differ because the browser is per-user while the CDN is shared across all viewers.

## Checklist: ISR-Cacheable Route on Vercel

- [ ] Zero Request/URL/cookie/header access in handler
- [ ] Prisma calls wrapped in try/catch (build-time safety + runtime resilience)
- [ ] `export const revalidate = N` (optional but recommended for ISR)
- [ ] Cache-Control header includes `s-maxage` for CDN
- [ ] Local build passes: `npm run build` with dummy env vars
- [ ] Production `curl -I` confirms `s-maxage` present + `cf-cache-status` HIT/STALE

### What NOT to do
- Don't read `req.url` even if you don't use it (`const url = req.url` is enough to kill caching)
- Don't use `cookies()` or `headers()` in ISR routes (these are Request-derived)
- Don't set `export const dynamic = 'force-dynamic'` unless you need per-request rendering
