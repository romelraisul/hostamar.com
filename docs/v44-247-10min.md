# V44 — 19 employees 24/7, 10-min pulse, drift-gated agent wakes

**Date:** 2026-09-21 · **Status:** SHIPPED

## What "24/7 every 10 min" actually means here (and why)

17 lane cron jobs now tick every **10-13 min round-robin** (staggered so they never re-align). Each tick runs a cheap deterministic pulse script; the agent (LLM) wakes **only when the pulse output changes** = real drift. This is 24/7 monitoring with 10-min resolution at near-zero token cost — 17 full LLM runs every 10 min on a free upstream would 429 itself to death (proven live: every full-fleet wake burst = 429/timeout storm).

## Root causes found + fixed (the real reason lanes were silent)

1. **`:8181` forwarder was single-threaded** (`socketserver.TCPServer`) — every concurrent request queued behind one `curl.exe` interop call. Fixed → `ThreadingTCPServer` (5 parallel 200s in ~40ms, was timeout). `wsl-browser-bridge/wsl-8181-forward.py`
2. **OmniRoute `api_keys` was empty** (V41) → hermes config key `no-key` 401'd → "Connection error" on all jobs. Config now uses `sk-hostamar-wsl-2026`.
3. **Model `auto`/big-pickle 403** upstream (transient) — jobs pinned to `opencode/muse-spark-1.3-contributor-free` via stable `:8181`.
4. **Monitor scripts took no args** — `lane-pulse-check.sh nova` treated as one filename. Fixed with 12 per-lane wrapper scripts `lane-<slug>-pulse.sh`.
5. **Pulse output had a timestamp** → gate saw "changed" every tick → every tick woke the agent. Removed → deterministic output, gates hold.
6. **Error-retry loop**: errored jobs got re-armed as FULL runs (not monitor ticks) → storm. Cleared `last_status` so gates take over.

## Architecture shipped

- `~/.hermes/scripts/lane-pulse-check.sh` — deterministic pulse: site/tv/models/drive/admin status + OmniRoute liveness → `verdict=HEALTHY|ALERT`
- 12 wrappers `lane-<slug>-pulse.sh` (reel bazaar quill nova forge pulse orion vertex ledger scout warden oracle)
- All 12 lane jobs: `monitor_script` wired, intervals 10-13 min, never re-align
- Atlas/Echo/Channel/Guard keep their existing lane-specific monitors (same pattern, already worked)
- Talk channel = `FleetEvent` (ops feed) + `~/memories/consensus.md` V44 protocol section — lanes read each other's events at shift start
- On drift: agent wakes with the pulse diff injected, works the V43 task board, reports via `fleet-report-push.sh` → Fleet tab + FleetEvent
